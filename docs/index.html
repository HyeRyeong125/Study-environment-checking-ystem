Vision · User Scenario

집중의 25분 (사용자 시나리오)

📌 상황

기말고사 준비 중인 학생 '수진'은 매일 오후 2시부터 공부를 시작한다.

⏱️ 14:00 ~ 14:25 (25분)

EcoMind를 켜고 포모도로 타이머를 시작. 웹캠과 센서가 자동으로 수진의 자세·집중도를 측정하고, 조명·소음 환경 점수를 계산한다. 화면 밝기가 어두우면 실시간으로 "조명을 밝혀보세요" 알림이 뜬다.

💾 14:25 ~ 14:30 (5분 휴식)

25분 작업이 끝나면 자동으로 세션이 종료된다. 백엔드가 수진의 집중도(82%), 환경 점수(78%), 포즈 안정성(85%)을 계산해 저장한다.

🤖 결과 분석

세션 종료 후 EXAONE이 자동으로 피드백을 생성: "오늘 당신의 집중도는 82%입니다. 조명(70점)을 개선하면 집중도가 5~10% 올라갈 수 있습니다. 어깨를 펴는 스트레칭을 추천합니다."

📊 주간 통계

일주일 데이터가 모이면, 수진은 '언제 가장 잘 집중하는지', '어떤 환경이 최적인지'를 그래프로 확인할 수 있다. 패턴 분석 결과: 오전 9~11시가 최고 집중도(89%), 조명 600~800lux일 때 최적.

기대 효과

개인화된 환경 최적화로 매주 3~5시간의 추가 효율성 확보

Q&A · Setup

개발 환경 설정

☕ Python 3.8+

  • Flask · REST API 서버
  • PySerial · Arduino 통신
  • paho-mqtt · MQTT 클라이언트
  • pip install -r requirements.txt

📨 Mosquitto MQTT

  • 로컬 브로커 (포트 1883)
  • brew install mosquitto
  • mosquitto 실행
  • 또는 Docker: docker run -d -p 1883:1883 eclipse-mosquitto

🔧 Arduino IDE 2.x

  • PubSubClient 라이브러리 필수
  • 보드: Arduino Uno
  • 포트: COM3 / /dev/ttyUSB0 확인
  • 업로드: sensor_sketch.ino 컴파일 & 전송

🗄️ Database

  • 개발: H2 (설치 불필요, 자동 생성)
  • 프로덕션: MySQL 5.7+
  • .env에서 DB_TYPE=h2 / mysql 지정
  • 프로덕션 마이그레이션 시 dump 파일 제공

🌐 Frontend 환경

  • Chrome 90+ (웹캠 권한 필수)
  • MediaPipe CDN 자동 로드
  • localhost:3000 에서 자동 권한 승인
  • HTTPS 배포 시 명시적 권한 요청

⚙️ 환경 변수 (.env)

  • SERIAL_PORT=/dev/ttyUSB0 (Arduino)
  • MQTT_BROKER=localhost:1883
  • FLASK_PORT=3000
  • EXAONE_API_KEY=your_key_here
  • DB_TYPE=h2 (dev) / mysql (prod)

Fundamentals · Troubleshooting

센서 연동 시행착오

❌ 1단계: Arduino 초기 연동 실패

문제: PySerial로 Arduino 포트를 열었지만 데이터가 수신되지 않음. 시리얼 모니터에는 정상 출력되는데 Python에서만 읽지 못함.

원인: 보드 리셋 타이밍 불일치 — Arduino가 재부팅되면서 버퍼 비우기 발생

해결: 연결 후 2초 대기 + try-except로 첫 데이터 버림 + 재시도 로직 구현

❌ 2단계: MQTT 메시지 손실

문제: MQTT로 센서 데이터를 발행했지만 백엔드에서 간헐적으로 수신하지 못함. 특히 네트워크 지연 발생 시 메시지 손실

원인: QoS 0 (최대 1회) 설정 — 브로커와 구독자 연결 끊김 시 메시지 버림

해결: QoS 1로 변경 (최소 1회 보장) + Mosquitto에서 영속성 활성화 + 재연결 지수백오프 구현

❌ 3단계: MediaPipe 웹캠 권한 문제

문제: 로컬호스트에서는 웹캠이 켜지는데 HTTPS 배포 환경에서 권한 요청이 자동으로 거부됨

원인: 일부 브라우저가 HTTPS 미지원 도메인에서 MediaDevices API 차단

해결: GitHub Pages HTTPS 인증서 갱신 + manifest.json에 camera 권한 명시 + 사용자에게 명시적 허용 유도

❌ 4단계: MediaPipe 성능 저하

문제: 웹캠 해상도가 1080p일 때 MediaPipe 처리가 프레임 지연 발생 (CPU 사용률 85%+)

원인: 모든 프레임을 MediaPipe로 분석 시도 → GPU 리소스 부족

해결: 입력 해상도를 640x480으로 다운스케일 + 매 2프레임마다 분석 (프레임 스킵) + 결과 캐싱

⚠️ 5단계: 조도/소음 센서 불안정

문제: 조도 센서가 어두운 환경에서 0 고정 + 소음 센서가 튀는 값 반복

원인: 센서 노이즈 + ADC 변환 과정에서의 양자화 오차

해결: 이동 평균(Moving Average) 필터 적용 (과거 5개 샘플) + 범위 검증 (0~1023 범위 클리핑)
